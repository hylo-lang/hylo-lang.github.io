## Environment Setup
You can either [set up the environment manually](#option-2-manual-installation), or use a devcontainer (recommended).

### Option 1: Devcontainer

A [development container](https://containers.dev/) allows us to use a pre-built Docker image,
[hylo-dev-toolchain](https://github.com/hylo-lang/hylo-dev-toolchain) as our development environment. To use it, we need a container
Runtime such as Docker. Using VSCode has the best devcontainer integration, but others may also
work.

   <TabItem label="Windows">

       Docker runs inside WSL 2 on Windows.

       <Steps>
           1. **Install WSL 2**, following
              [Microsoft's guide](https://learn.microsoft.com/en-us/windows/wsl/install).
              In a terminal running as administrator:

              ```bash frame=none
              wsl --install
              ```
              Then reboot your machine, and if prompted, create a WSL Linux user.

           2. **Install [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/)**.
           3. **Enable [WSL Integration in Docker](https://docs.docker.com/desktop/features/wsl/):**
              Open Docker Desktop, and go to _Settings (gear icon) > Resources > WSL Integration_, and enable WSL
              integration for the distro you have installed.

           4. [Set up the Git Credential Manager in WSL](https://learn.microsoft.com/en-us/windows/wsl/tutorials/wsl-git)
       </Steps>
   </TabItem>
</Tabs>

#### Bonus: Opening the container from the command line

If you use a terminal based code editor, you can edit the sources locally, and perform building and testing
using the [devcontainer CLI](https://github.com/devcontainers/cli):

```bash frame=none
npm install -g @devcontainers/cli

devcontainer up --workspace-folder .
devcontainer exec --workspace-folder . swift build
devcontainer exec --workspace-folder . swift test
devcontainer down --workspace-folder . # warning: removes the container
```

#### Bonus: Building against the Debug LLVM

By default, the container uses `MinSizeRel` LLVM. If you need to debug some LLVM internals,
you can make the container use the `Debug` image version by setting the environment variable
`HYLO_LLVM_BUILD_TYPE` to `Debug`:

```bash frame=none
export HYLO_LLVM_BUILD_TYPE=Debug
```

### Option 2: Manual Installation

import WindowsDevMode from './windows-dev-mode.png';

<Tabs syncKey="os">
    <TabItem label="Linux">
        <Steps>
            1. **Install Swift 6.3.2 or newer**, using [swiftly](https://github.com/swiftlang/swiftly), Swift's
               toolchain installer.

            2. **Install pkg-config**, which Swift Package Manager uses to find LLVM.

               ```bash frame=none
               sudo apt install pkg-config
               ```

            3. **Download Hylo's latest LLVM build** from
               [the llvm-build releases page](https://github.com/hylo-lang/llvm-build/releases) and extract it
               somewhere permanent.

               We build LLVM for x64 and arm64, requiring glibc 2.39+ (Ubuntu 24.04+). If your platform is not among
               these, you will need to acquire an LLVM 23 distribution that works for you, and generate `llvm.pc` using
               our [scripts](https://github.com/hylo-lang/llvm-build#using-an-existing-llvm-build-with-swift).

            4. **Tell pkg-config where to locate LLVM.**
               The archive contains a `pkgconfig` subdirectory holding `llvm.pc`, which must be exposed on
               `PKG_CONFIG_PATH`:

               ```bash frame=none
               export PKG_CONFIG_PATH="<LLVM>/pkgconfig:$PKG_CONFIG_PATH"
               ```

               Confirm it resolves:

               ```bash frame=none
               pkg-config --modversion llvm
               ```
        </Steps>
    </TabItem>
    <TabItem label="macOS">
        <Steps>
            1. **Install Swift 6.3.2 or newer**, from [swift.org](https://www.swift.org/install/macos/), or by
               installing Xcode.

            2. **Install pkg-config**, which Swift Package Manager uses to find LLVM.

               ```bash frame=none
               brew install pkgconf
               ```

            3. **Download Hylo's latest LLVM build** from
               [the llvm-build releases page](https://github.com/hylo-lang/llvm-build/releases) and extract it
               somewhere permanent.

               We build LLVM for Apple silicon and Intel, requiring macOS 26+. If your platform is not among these,
               you will need to acquire an LLVM 23 distribution that works for you, and generate `llvm.pc` using our
               [scripts](https://github.com/hylo-lang/llvm-build#using-an-existing-llvm-build-with-swift).

            4. **Tell pkg-config where to locate LLVM.**
               The archive contains a `pkgconfig` subdirectory holding `llvm.pc`, which must be exposed on
               `PKG_CONFIG_PATH`:

               ```bash frame=none
               export PKG_CONFIG_PATH="<LLVM>/pkgconfig:$PKG_CONFIG_PATH"
               ```

               <Aside type="tip" title="Xcode needs the .pc file installed">
                   Xcode ignores `PKG_CONFIG_PATH`, so if you build through Xcode rather than the
                   command line, install the file into a directory Xcode already searches. The
                   archive includes a script for this:

                   ```bash frame=none
                   cd <LLVM>/pkgconfig
                   ./install-pc.sh llvm.pc /usr/local/lib/pkgconfig/
                   ```
               </Aside>

               Confirm it resolves:

               ```bash frame=none
               pkg-config --modversion llvm
               ```
        </Steps>
    </TabItem>
    <TabItem label="Windows">
        <Steps>
            1. **Install Swift 6.3.2 or newer**, from [swift.org](https://www.swift.org/install/windows/).

            2. **Enable developer mode** in _Settings > System > For developers > Developer Mode_:
               <Image
                    src={WindowsDevMode}
                    alt="Settings > System > For developers > Developer Mode"/>

            3. **Install pkg-config**, which Swift Package Manager uses to find LLVM.

               ```powershell frame=none
               choco install pkgconfiglite
               ```

               Or download it from [SourceForge](https://sourceforge.net/projects/pkgconfiglite/).

            4. **Download Hylo's latest LLVM build** from
               [the llvm-build releases page](https://github.com/hylo-lang/llvm-build/releases) and extract it
               somewhere permanent.

               We build LLVM for x64 and arm64, requiring Windows 11. If your platform is not among these, you will
               need to acquire an LLVM 23 distribution that works for you, and generate `llvm.pc` using our
               [scripts](https://github.com/hylo-lang/llvm-build#using-an-existing-llvm-build-with-swift).

            5. **Tell pkg-config where to locate LLVM.**
               The archive contains a `pkgconfig` subdirectory holding `llvm.pc`, which must be exposed on
               `PKG_CONFIG_PATH`:

               ```powershell wrap title="PowerShell"
               $env:PKG_CONFIG_PATH = "<LLVM>\pkgconfig;$env:PKG_CONFIG_PATH"

               # Persist across sessions:
               [Environment]::SetEnvironmentVariable("PKG_CONFIG_PATH", $env:PKG_CONFIG_PATH, "User")
               ```

               Confirm it resolves:

               ```powershell frame=none
               pkg-config --modversion llvm
               ```
        </Steps>
    </TabItem>
</Tabs>


## Build and test

```bash frame=none
swift build  # build in debug mode, without tests
swift test  # build and run tests in debug mode
swift test -c release  # build and run tests in release mode
swift test --parallel  # build and run tests in parallel
```

## Compiler Tests

A large part of our test suite is generated from hylo programs at
[`Tests/CompilerTests/{positive,negative}/*.hylo`](https://github.com/hylo-lang/hylo-new/tree/main/Tests/CompilerTests).
See instructions in the [Compiler Testing Guide](https://github.com/hylo-lang/hylo-new/blob/main/Tests/CompilerTests/README.md).

## Building for cross-compilation

By default, a custom-built `hc` can only generate code for the machine it is running on. To build a cross-capable
version, supply the `SWIFTY_LLVM_CROSS_COMPILATION_ENABLED` flag (already set in official releases):

```bash wrap frame=none
swift build -c release -Xswiftc -DSWIFTY_LLVM_CROSS_COMPILATION_ENABLED
```
