The <a href={compilerRepoLink}>Hylo compiler</a> is written in Swift, links against LLVM 23, and can be built using the
Swift Package Manager.


## Environment Setup
You can either [set up the environment manually](), or use a devcontainer (recommended).

### Option 1: Devcontainer

A [development container](https://containers.dev/) is a Docker image described by
the repository itself. Ours is built from
[hylo-dev-toolchain](https://github.com/hylo-lang/hylo-dev-toolchain), and ships Swift, LLVM with
assertions enabled, pkg-config, and the environment variables that connect them.
Nothing needs installing on your machine beyond Docker.

First set up a container runtime for your operating system, then open the container
in your editor.


#### Set up Docker

<Tabs syncKey="os">
   <TabItem label="Linux">
       Install [Docker Engine](https://docs.docker.com/engine/install/ubuntu/), then follow
       its [post-installation steps](https://docs.docker.com/engine/install/linux-postinstall/) so you can run
       Docker without `sudo`: TODO verify

       ```bash frame=none
       sudo usermod -aG docker $USER
       newgrp docker
       ```
   </TabItem>
   <TabItem label="macOS">
       Install [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/).
   </TabItem>
   <TabItem label="Windows">

       Docker runs inside WSL 2 on Windows.

       <Steps>
           1. **Install WSL 2**, following
              [Microsoft's guide](https://learn.microsoft.com/en-us/windows/wsl/install).
              In a terminal running as administrator:

              ```bash frame=none
              wsl --install
              ```
              Then reboot your machine, and if prompted, create a WSL Linux user.

           2. **Install Docker Desktop** and enable its WSL 2 backend, as described in
              [Docker's WSL documentation](https://docs.docker.com/desktop/features/wsl/).
           3. **Enable WSL Integration in Docker**
              Open Docker Desktop, and go to Settings (gear icon) → Resources → WSL Integration, and enable WSL
              integration for the distro you have installed.

           4. [Set up the Git Credential Manager in WSL](https://learn.microsoft.com/en-us/windows/wsl/tutorials/wsl-git)

           5. **Clone the repository inside WSL**. Avoid cloning on a Windows drive to avoid a huge slow-down and
              newline-related problems):
              ```bash frame=none
              git clone https://github.com/hylo-lang/hylo-new
              git submodule update --init
              ```
       </Steps>
   </TabItem>
</Tabs>


#### Open the container in VSCode

<Steps>
    1. Install the [Dev Containers extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers).
       On Windows, also install the [WSL extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-wsl)
       and open the folder through it.

    2. Open the `hylo-new` folder, then run `Dev Containers: Reopen in Container`
       from the command palette.

    3. Build the compiler from the integrated terminal, which is now running inside
       the container:

       ```bash frame=none
       swift build
       ```
</Steps>

Congrats, now you are ready to go!

#### Bonus: Opening the container from the command line

If you use a terminal based code editor, you can edit the sources locally, and perform building and testing
using the [devcontainer CLI](https://github.com/devcontainers/cli):

```bash frame=none
npm install -g @devcontainers/cli

devcontainer up --workspace-folder .
devcontainer exec --workspace-folder . swift build
devcontainer exec --workspace-folder . swift test
devcontainer down --workspace-folder .` # warning: removes the container
```

#### Bonus: Building against the Debug LLVM

Two LLVM configurations are published, both with assertions enabled: `MinSizeRel`
and `Debug`. The container uses `MinSizeRel` by default. To get a `Debug` build,
set the following environment variable before building your devcontainer:

```bash frame=none
export HYLO_LLVM_BUILD_TYPE=Debug
```

### Option 2: Manual Installation

<Steps>
    1. **Install Swift 6.3.2 or newer.**

       <Tabs syncKey="os">
           <TabItem label="Linux">
               Use [swiftly](https://github.com/swiftlang/swiftly), Swift's
               toolchain installer.
           </TabItem>
           <TabItem label="macOS">
               Install from [swift.org](https://www.swift.org/install/macos/), or
               install Xcode.
           </TabItem>
           <TabItem label="Windows">
               Install from
               [swift.org](https://www.swift.org/install/windows/).
           </TabItem>
       </Tabs>

    3. **Install pkg-config**, which Swift Package Manager uses to find LLVM.

       <Tabs syncKey="os">
           <TabItem label="Linux">
               ```bash frame=none
               sudo apt install pkg-config
               ```
           </TabItem>
           <TabItem label="macOS">
               ```bash frame=none
               brew install pkgconf
               ```
           </TabItem>
           <TabItem label="Windows">
               ```bash frame=none
               choco install pkgconfiglite
               ```
               Or download from [SourceForge](https://sourceforge.net/projects/pkgconfiglite/).
           </TabItem>
       </Tabs>

    4. **Download Hylo's latest LLVM build** from
       [the llvm-build releases page](https://github.com/hylo-lang/llvm-build/releases) and extract it somewhere permanent.

       Currently, we build LLVM for the following platforms:

        | Platform | Architectures | Minimum version |
        | --- | --- | --- |
        | Linux | x64, arm64 | glibc 2.39+ (Ubuntu 24.04+) |
        | macOS | Apple silicon, Intel | macOS 26+ |
        | Windows | x64, arm64 | Windows 11 |

       If your platform is not among these, you will need to acquire an LLVM 23 distribution that works for you, and
       generate llvm.pc using our [scripts](https://github.com/hylo-lang/llvm-build#using-an-existing-llvm-build-with-swift).

    4. **Tell pkg-config where to locate LLVM.**
       The archive contains a `pkgconfig`
       subdirectory holding `llvm.pc`, which must be exposed on `PKG_CONFIG_PATH`:

       <Tabs syncKey="os">
           <TabItem label="Linux">
               ```bash frame=none
               export PKG_CONFIG_PATH="<LLVM>/pkgconfig:$PKG_CONFIG_PATH"
               ```
           </TabItem>
           <TabItem label="macOS">
               ```bash frame=none
               export PKG_CONFIG_PATH="<LLVM>/pkgconfig:$PKG_CONFIG_PATH"
               ```
               <Aside type="tip" title="Xcode needs the .pc file installed">
                   Xcode ignores `PKG_CONFIG_PATH`, so if you build through Xcode rather than the
                   command line, install the file into a directory Xcode already searches. The
                   archive includes a script for this:

                   ```bash frame=none
                   cd <LLVM>/pkgconfig
                   ./install-pc.sh llvm.pc /usr/local/lib/pkgconfig/
                   ```
               </Aside>
           </TabItem>

           <TabItem label="Windows">
               In PowerShell:

               ```powershell wrap frame=none
               $env:PKG_CONFIG_PATH = "<LLVM>\pkgconfig;$env:PKG_CONFIG_PATH"
               ```

               To persist it across terminals:

               ```powershell wrap frame=none
               [Environment]::SetEnvironmentVariable("PKG_CONFIG_PATH", $env:PKG_CONFIG_PATH, "User")
               ```
           </TabItem>

       </Tabs>

       Confirm it resolves:

       ```bash frame=none
       pkg-config --modversion llvm
       ```
</Steps>


## Build and test

```bash frame=none
swift build
swift test
```

## Compiler Tests

A large part of our test suite is generated from hylo programs at
[`Tests/CompilerTests/{positive,negative}/*.hylo`](https://github.com/hylo-lang/hylo-new/tree/main/Tests/CompilerTests).
See instructions in the [Compiler Testing Guide](https://github.com/hylo-lang/hylo-new/blob/main/Tests/CompilerTests/README.md).

## Building for ross-compilation

By default, a custom-built `hc` can only generate code for the machine it is running on
To build a cross-capable version, supply the `SWIFTY_LLVM_CROSS_COMPILATION_ENABLED` flag (already set in official releases):

```bash wrap frame=none
swift build -c release -Xswiftc -DSWIFTY_LLVM_CROSS_COMPILATION_ENABLED
```
